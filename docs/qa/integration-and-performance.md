# G01: сквозные проверки конструктора и производительности

Это программная приёмка интеграции. Она не подтверждает инженерную точность, согласование реальных товаров, прохождение пилота или готовность к передаче версии 1.0.

| Контур | Автоматическое доказательство |
|---|---|
| Большой проект | Комплектная фикстура из 12 комнат, 48 петель, 6 независимых стендов, 220 компонентов и 400 соединений проходит тот же JSON-импорт, редактор и расчётный Worker, что пользовательский проект. Три типа контрольных сопротивлений не находятся в панели доступного к установке оборудования и не являются реальными товарами. |
| Данные и повторяемость | Две редакции, сравнение на одном модельном тике, автосохранение, новое открытие, экспорт/импорт копии, повтор запечатанного прогона с положительным расходом. В отдельно проверенной схеме учебный аналог сохраняет точный артикул и происхождение, но не выдаёт профиль источника за паспортный. |
| Упакованный Windows ZIP | Исполняемый файл запускается из пути с пробелами и кириллицей с программно заблокированным HTTP(S). Проверяются видимый клавиатурный фокус, десятичная запятая, режим принудительных цветов на уровне Chromium, 2D/3D и деградация до 2D, Worker, локальный каталог, сохранение непосредственно перед выходом, открытие проекта и уроки. Настройки защиты, системные темы и полностью отключённая сеть на сотрудническом ПК проверяются отдельно. |
| Сбой графики | Браузерный тест вызывает реальную потерю контекста WebGL и подтверждает возврат в 2D с сохранением выделения и связей. Это не означает, что 3D поддерживает каждый компьютер. |

## Замеры

- В браузерном прогоне фиксируется время навигации до готовности, без старта Chromium. В Electron замер начинается перед запуском нового процесса с чистым профилем и заканчивается, когда доступен интерактивный экран. Это не замер с очищенными дисковыми кешами ОС.
- Для редактора берётся время от реального клика переключателя слоя «Вода» до следующей возможности отрисовки после обновления схемы. Для команд отдельно фиксируются подтверждение Worker и первый возвращённый снимок с применённым изменением на следующем тике при ×1. Измеритель только наблюдает сообщения; не отвечает за Worker и не меняет часы.
- В 3D измеряется интервал кадров браузера при перетаскивании мышью с работающим расчётом. При устойчивом снижении частоты графика уменьшает разрешение холста и плотность частиц без изменения расчётов; качество повышается после достаточно длинной серии быстрых кадров. Записываются OS, CPU, RAM, Chromium/Electron, GPU, масштаб окна и холста, видимая область, reduced motion, сырые данные и p95 ближайшего ранга. `EDUCATIONSIM_PERF` в логе содержит сводку. Окно замера по умолчанию 2,5 с с программным WebGL: это проверка воспроизводимости, а не сравнение с целевыми нормами.
- Низкие показатели на машине сборки не скрываются и не считаются автоматически отказом на целевой машине. Отсутствие результата на целевой машине не считается прохождением. Замеры не подменяют визуальную проверку системного контраста, читаемости при Windows scaling и состояния приложения на обычной учётной записи.

### Инструкция для эталонного Windows 11 x64

В чистом запущенном профиле и с **физически отключённой сетью** использовать тот же ZIP, который предназначен для передачи. Графический драйвер должен быть включён; выбрать экран 1920×1080 и проверить 100% и 150% масштаб. На тестовой машине инструменты Playwright устанавливаются заранее, но сам продукт не должен зависеть от Node.js. На машине сотрудника дополнительно выполнить запуск и действия из R19 без этих инструментов.

```powershell
$env:EDUCATIONSIM_DESKTOP_EXE = 'C:\Проверка EducationSim\EducationSim.exe'
$env:EDUCATIONSIM_PERFORMANCE_TARGET = '1'
npm run test:desktop -- tests/desktop/performance.spec.ts --workers=1
```

Скрипт не форсирует программный WebGL в режиме цели, увеличивает выборку движения камеры до 30 секунд и проверяет время старта ≤4 с, p95 кадра большой сцены ≤33 мс, p95 реакции редактора ≤150 мс, p95 подтверждения Worker ≤500/1000 мс и p95 следующего снимка ≤1500/2000 мс для малого/большого проекта. Сохранить файл замера, дату, фактический компьютер, режим питания, масштаб, версии и SHA-256 ZIP; повторить замер после исправления любого выхода за пределы. Только результаты на таком ПК могут закрыть соответствующую часть R18/R19. Для случая слабой графики проверять также переход в 2D и сохранность проекта.
